# Known Release Limitations

- User screenshots and Playwright traces require scoped, expiring artifact tickets bound to user/project/run/kind; current project membership is checked on retrieval. A ticket remains a temporary bearer capability and must not be persisted or logged. Final Compose smoke verified screenshot retrieval (HTTP 200), trace range retrieval (HTTP 206), and Trace Viewer rendering. The full ticket lifecycle/security matrix (expiry, revocation, altered identifiers, cache/referrer/log handling) remains unverified.
- The production dependency audit reports 3 Moderate advisories through `@fastify/static@10.1.3` → `glob@13.0.7` → `minimatch@10.2.6`, with 0 High. The current runtime baseline is Node 20, while the candidate fixed static package chain declares Node >=22. Do not force an engine-incompatible upgrade; reassess after a deliberate runtime baseline change.
- HTTP Request blocks private/VPC destinations unless an administrator configures the server-side exact-host allowlist. Project users cannot relax that global policy. A pinned-DNS regression was fixed for Node's `all:true` callback contract; broader DNS rebinding/redirect integration remains a security gate.
- A killed worker can repeat external side effects from an already-started browser, HTTP or SQL step even though internal SuiteRun/TestRun creation and coordinator transitions are designed to be idempotent. Exactly-once behavior for arbitrary external systems is not guaranteed.
- Security Gate 1 remains PARTIAL: the Check-import IDOR is fixed with a regression test, but the full route-by-role and all-32-MCP-tool matrix is an accepted known coverage limitation. Source inventory and selected tests are not a full authorization sign-off. Do not expand this audit absent concrete evidence of a critical vulnerability.
- The Check Editor's confirmed Viewer fail-open during unresolved role loading is fixed in the current working tree and the final Owner/Editor/Viewer UI smoke passed. This does not replace server-side authorization; Security Gate 1 remains PARTIAL under the accepted coverage scope.
- Provider-backed PostgreSQL and MySQL integration passed on disposable services. HTTP-to-SQL and HTTP schedule integration passed. The isolated mixed Check Generate → HTTP POST → SQL SELECT/assertion → Browser assertion → HTTP DELETE → SQL cleanup passed all 7 steps; this does not cover every provider or policy combination.
- Sequential Suite reliability and worker restart tests passed for selected cases. Scheduler timezone/restart/occurrence behavior, all recovery cut points, Redis reconnect and the full Independent parallel isolation matrix remain unverified.
- A real isolated Docker Compose stack ran Browser Check, HTTP Check, Sequential Suite, backend restart/persistence checks, screenshot retrieval and Playwright Trace Viewer. The viewer produced one non-blocking console message for replay of a `data:` URL; timeline, actions, and screenshot were visible. Full artifact-ticket lifecycle and security coverage remain open.
- The full UI E2E initially exposed project creation synchronization flakiness (initial empty/loading state and stale in-flight `/projects` response), and later confirmed that Viewer Check Editor controls failed open while role data was unresolved. The smoke now waits for loaded/list state and the editor only grants write access to confirmed OWNER/EDITOR or system admin. Final isolated suite passed 19/19; broader role/API authorization coverage remains separate.
- The isolated E2E harness had reached the global API limit under browser smoke traffic. It now configures `RATE_LIMIT_MAX=1000` only for its temporary backend; the dedicated `/auth/login` limit remains 10 requests per 5 minutes and production configuration is unchanged.
- The frontend production bundle still triggers Vite's large-chunk warning. This is a performance limitation rather than a confirmed security defect.
- The v0.4.0 source is merged to `main`, but the Git tag, GitHub Release and Docker Hub `0.4.0` image tags have not been published. On 2026-11-09 the three WrightTest image repositories exposed `0.3.0` and `latest`; do not use `0.4.0` in a pull command until all three tags exist.
- PR #8's Windows checkout fix (`*.sh text eol=lf`) is merged and preserves contributor `hendricktlv`'s original commit. PR CI passed; its Release Validation failed on 10 E2E smoke cases against the pre-PR #9 base. After merge, both CI and Release Validation passed on current `main` (`1a3119b`; runs 42592608010 and 42592608099). The original PR failure remains historical evidence and is not represented as a pass.
- Phase 8.3 current audit (2026-11-09) reran the isolated UI suite successfully (19/19), backend unit suite (99 passed, 0 failed, 3 opt-in skips), backend/frontend TypeScript, E2E typecheck, MCP build/tests (16/16), frontend build, Prisma validation and i18n validation. The three opt-in DB/worker tests passed separately on disposable infrastructure; an aggregate run with the private-target integration flag conflicts with the ordinary loopback-denial unit test and is not reported as a full pass.
- Final Release Smoke passed for Compose build/runtime, the 7-step mixed Check, Schedule and Sequential Suite basics, worker restart (2/2), and screenshot/trace viewer delivery. GitHub Actions was not run. Remaining release limitations include Security Gate 1 PARTIAL (accepted scope), three Moderate dependency advisories from the dated audit, the full artifact-ticket lifecycle matrix, and broader schedule/recovery combinations. Re-run time-sensitive dependency and CI checks before publishing.
